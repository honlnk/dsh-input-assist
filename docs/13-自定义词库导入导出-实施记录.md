# 开发记录 · 自定义词库导入/导出

日期：2026-09-13 · 对应 README 状态清单「自定义词库导入/导出」。

## 1. 背景与问题

自定义词库的存储设计本是行式文本（`错词 => 正词` 一行一条，与内置
`data/*.txt` 同语法），`user-dict.ts` 头注释写明「复制粘贴即是导入/导出」——
textarea 时代确实成立。但 0.4 把编辑器改成了成对词条列表（docs/11）之后：

- **导出没了**：没有整块文本可全选复制，词条想搬走只能一条条手抄；
- **导入不通**：多行文本粘进某个「错词」输入框，只会触发 wrongSpace 报错；
- 帮助文案还写着「换浏览器需自行复制」，已经无处可复制——是句误导。

本篇补齐文件级的导入/导出/复制，全部纯浏览器侧，host 半边与 RPC 不动。

## 2. 方案

### 格式：就是存储格式

导出文件即 `错词 => 正词` 行式文本，外加两行 `#` 注释头（导入时被同一
解析器跳过）。与内置词库、localStorage 存储三方同构，零新语法、零转换：
内置词库文件可以直接导入，导出的文件也可以直接贡献给 `data/`。

### 纯逻辑（src/settings-form.ts）

- 单行判定抽成 `classifyUserDictLine`（entry / skip / invalid），
  `parseUserDictPairs` 与新导入解析共用，行为不变；
- `importUserDictText(text)`：文本 → `{ pairs, ignored }`，ignored = 有内容
  但没解析成词条的行数（导入提示「忽略 N 行」），注释/空行不计；
- `mergeUserDictPairs(current, incoming)`：合并语义——
  - 同（trim 后）错词**就地更新**正词、保持原顺序；其余按导入顺序追加；
  - incoming 内部同名**后者覆盖前者**（与词典文本覆盖语义一致，合并前先
    去重，保证 added/updated 计数只描述对现有列表的影响）；
  - 半填行（只有错词）被导入补全；空行不被匹配、原样保留；
  - 输出行带 `fromCurrent`（命中的当前行下标，追加为 -1）：UI 借此保留
    旧行 id，FLIP 不整列重挂；
  - **不做上限/去重校验**——结果进暂存列表，`checkUserDictPairs` 在保存时
    统一把关（导入超 2000 条 → overflow 报错拦住保存，与手填同路）；
- `exportUserDictText(pairs)`：注释头 + 有效词条（半填行不导出）。

### UI（src/client.ts 设置卡片词库区块）

标题行右侧（条数计数旁）加「导入 / 导出 / 复制」三个小按钮：

- **导出**：`Blob + URL.createObjectURL + a[download]` 下载
  `dsh-input-assist-dict.txt`，导出的是**当前所见列表**（含未保存修改，
  tooltip 注明）；
- **复制**：`navigator.clipboard.writeText` 写同格式文本（127.0.0.1 是安全
  上下文，用户手势内调用；失败走降级提示）；
- **导入**：隐藏 `<input type=file accept=".txt,text/plain">`，选中后
  `file.text()` → 解析 → 合并进**暂存列表**（`commitUserRows` 走 FLIP），
  flash 提示「导入完成：新增 a · 更新 u · 忽略 m 行」——落暂存意味着过目
  后仍要点保存，不会一键污染已存词库；`value` 读后即清，同文件可重复选；
  超 1MB / 读取失败 / 无可识别词条各有独立提示；
- flash 是 3s 自动消失的瞬时 `role=status` 行，与 localStorage 写失败那路
  （常驻 `ia_sfailed`）分开；
- i18n 中英双语补 17 键；帮助文案的「换浏览器需自行复制」改为
  「换浏览器用『导出 / 导入』搬运」，修正过时描述。

### 样式

`.ia_udHead`（计数 + 工具组右对齐容器）/ `.ia_udTools` / `.ia_udTool`
（描边小方按钮，与删除按钮同语言）/ `.ia_udFile{display:none}` /
`.ia_udNote`（flash 行），全部走既有 design-token 变量。

## 3. 验证

`npm test` 95 例全过（新增 4 例，均在 bundle 守卫 `test/settings-card.test.js`）：

- `importUserDictText`：词条与忽略行分开计数、注释空行不算忽略、空文本；
- `mergeUserDictPairs`：同错词就地更新 + 新词追加 + 导入内同名后者覆盖
  （计数只算一次）；半填行被补全、空行不被匹配；
- `exportUserDictText`：注释头、半填行不导出、导出 → 导入 → 并入空表
  全链路回环。

真实 Chrome 验收：见 §5。

## 4. 边界与取舍

- 导出的就是「所见列表」：未保存的手填修改也在里面（tooltip 说明），
  避免再引入「导已存 vs 导暂存」二选一；
- 文件里的半填/畸形行不计入 pairs 但计入 ignored，用户能看到丢了多少行；
- 不做「导出为 JSON/CSV」等富格式：单一行式格式已是三方通用语，
  富格式只增加解释成本；
- 导入不做「替换模式」（只合并）：要清空重来可用列表 × 删光或导出空
  文件语义，避免多一个危险按钮。

## 5. 真机验收记录（2026-09-13）

dsh（127.0.0.1:3080）运行中原包热更（client bundle 按内容哈希 ?rev= 即时读
盘，host 未动无需重启），页面刷新后 Settings → Plugins → Input Assist 展开
（界面英文 locale）。浏览器 localStorage 预置 3 条词条（`帐号 => 账户`、
`再接再励 => 再接再厉`、`alot => a lot`）：

1. **导出**：埋点 `URL.createObjectURL` + `HTMLAnchorElement.prototype.click`
   后点「Export」——捕获 `download=dsh-input-assist-dict.txt`，blob 内容为
   两行 `#` 注释头 + 3 行词条（尾随换行），`revokeObjectURL` 在 click 后被调；
2. **复制**：包装（透传）`navigator.clipboard.writeText` 后点「Copy」——写入
   文本与导出一致，`readText` 回读首行即注释头，flash「Copied 3 entries」；
3. **导入合并**：构造文件（`# 注释` + `帐号 => 账号`（更新已存行）+
   `导入新词 => 导入正词`（新增）+ 1 行无分隔符坏行），`DataTransfer` 塞进
   隐藏 file input 触发 change——flash「Imported: added 1 · updated 1 ·
   ignored 1 lines」，`帐号` 行**就地更新**、新词末尾追加、注释不计忽略；
   meta 变「4 entries · Unsaved」，localStorage 未动（导入只进暂存）；
4. **保存落库**：点卡片底部「Save」——localStorage 写入 4 行（含更新后的
   `帐号 => 账号`），Unsaved 标记消失；
5. **坏文件**：全不可识别内容（2 行）→ flash「No recognizable entries in
   the file (one pair per line: wrong => right) · ignored 2 lines」，列表与
   存储均不动；
6. **布局**：截图目检标题行——「4 entries」计数与 Import / Export / Copy
   三枚描边小按钮同行右对齐，词条行对齐无破版；
7. **文案**：帮助文案尾部已是「use Export / Import to move it between
   browsers」（中文 locale 为「换浏览器用『导出 / 导入』搬运」）。

验收后测试数据已还原（localStorage 恢复为预置 3 条）。
