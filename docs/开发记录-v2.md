# v2 开发记录（2026-08-23）— 错别字提醒改版

> 需求：错字在文本中红字标注；逐条导航、只替换选中的那条；可"标记正确"豁免；配一套不冲突的快捷键。

## 交互设计

### 文中红字（镜像层）

dsh 输入框是原生 textarea，无法给部分文字上色。采用**镜像层**：在 `document.body` 挂一个 `position:fixed` 的 div，几何与 textarea 完全对齐（复制 computed font/padding/line-height，`clientWidth/Height` 定尺寸），内容与草稿同步渲染——干净文字渲染为透明（撑住换行布局），错字片段渲染为红色波浪线（`--dsw-alias-accent-danger`），**当前选中项**额外加红色底色。textarea 原生文字从透明层下透出，只有错字被"染红"。

- 滚动/缩放监听重同步（scroll 用 capture 捕获 textarea 滚动）
- 错字 span `pointer-events:auto`：**点红字直接选中该条**，其余区域穿透不影响输入
- 该技术与 dsh 官方 `decorations.ts` 的 mirror-layer、NovAI 的 GhostTextOverlay 同源

### 导航条（`conversation.input.dock`）

```
● 疑似错别字  ‹  2/3  ›  帐号→账号 · 通常为「账号」的误写      [修正] [标记正确] [忽略]
```

- `‹ ›` 上一个/下一个（循环），位置指示 `当前/总数`
- 中间实时显示当前项：原文（红、删除线）→ 修正词（加粗）· 理由
- **修正**：只替换当前选中项（`setDraft` 精确替换该 offset，替换前校验位置未失效），替换后自动复查
- **标记正确**：该处加入本次输入的忽略名单（红字消失、计数减少，草稿再变后重置）——不做全局词库豁免，避免一处正确导致他处真错被永久放过
- **忽略**：本次输入不再提醒（Esc 同效）
- 绝无全量替换；位置失配的条目自动从有效列表剔除

### 快捷键（经逐一冲突排查）

| 动作 | 快捷键 | 排查结论 |
| --- | --- | --- |
| 下一个错字 | `Ctrl+Shift+.` | Chrome/Edge/Firefox 页面内均无占用（mac 用 ⌃⇧.） |
| 上一个错字 | `Ctrl+Shift+,` | 同上 |
| 修正当前 | `Ctrl+Shift+F` | 浏览器无占用（仅 VS Code 桌面版有"全局搜索"，页面内无冲突） |
| 标记正确 | `Ctrl+Shift+G` | 无占用 |
| 忽略本次 | `Esc` | 建议条可见时优先关闭建议条，否则忽略错字提醒 |

刻意避开：`Tab`（补全采纳/焦点移动）、`Enter`/`Ctrl+Enter`（发送/插话）、方向键及 `Alt/Option+方向`（mac 切词、^↑ 调度中心）、`Ctrl+单字母`（Z/X/C/V/A/Y 撤销复制等）、`Ctrl+Shift+N/T/W`（浏览器保留）。所有快捷键**仅在输入框聚焦且有检出时**于捕获阶段接管，IME 组合期放行。

## 实现落点（lib/client.js）

- `effectiveIssues()`：位置校验 + 忽略名单过滤，导航与镜像层共用
- `navMove / navFixCurrent / navMarkCorrect`：纯状态操作 + setDraft
- `syncMirror()`：镜像层全量重建（草稿/检出/选中/忽略任一变化触发；由 TypoNav 组件的 useEffect 驱动）
- 快捷键并入既有 keydown 捕获拦截器（与 Tab/Esc 补全逻辑同处，Esc 有优先级仲裁）
- 调试钩子：`window.__iaApi`（navMove 等）、`window.__iaDebug`（渲染/调度状态）

## 验证状态

- ✅ 导航条真机渲染：`‹ 1/3 › 迫不急待→迫不及待·理由 [Fix][Mark correct][Dismiss]`
- ✅ 镜像层真机渲染：3 个红色错字 span、当前项高亮、字体/几何与 textarea 对齐（-apple-system 复制成功、387,363 定位正确）

- ⚠️ **点击按钮与快捷键的真机操作未能在此环境验证**：ZCode 内嵌浏览器（IAB）对主页面区域的点击派发和修饰键组合派发均有缺陷（dsh 自家非弹窗按钮同样不响应；focus 正常、渲染正常、几何/层级/pointer-events 排查无异常）。修正动作调用的 `inputActions.setDraft` 与官方 dsh-voice-input 生产用法相同。**请在真实 Chrome 中验证一轮**：打字出现红字 → 点红字/按 Ctrl+Shift+. 切换 → Ctrl+Shift+F 修正 → Ctrl+Shift+G 标记正确 → Esc 忽略；若按钮异常，控制台 `window.__iaApi.navMove(1)` 可直接驱动同一逻辑定位问题。
