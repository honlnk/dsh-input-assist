# 开发记录 · 流式渐进渲染

日期：2026-09-13 · 对应 README 状态清单「流式渐进渲染」——docs/12 在途取消
铺垫的另一半，也是状态清单最后一项待办。

## 1. 背景与决策

补全建议此前是「整段憋出来」：停笔 800ms 防抖后 host 发**非流式** FIM 请求，
等服务端生成完一次性返回，ghost 才整块弹出。流式改版让**首 token 到达即
上屏、文字随生成逐字变长**，期间随时 Tab 采纳已到部分 / Esc 掐断。

决策过程有个插曲：一度想以「补全接口不支持流式」为由放弃，核实 DeepSeek
官网 API 参考后推翻——FIM 端点 `/beta/completions` **明确文档化 `stream`
参数**（"以 SSE 形式流式发送消息增量，消息流以 `data: [DONE]` 结尾"），
配套 `stream_options.include_usage`；NovAI 的 `streamFimCompletion()` 也是
流式实现的现成先例。遂继续，并按需求做**冗余设计**：默认流式，设置页给
开关（`completionStream`，默认 `true`）可退回整段返回——第三方 OpenAI
兼容端点不支持的场合由用户自行关闭。

## 2. 传输层调研（本功能最大的前置不确定性）

cordis RPC 自定义通道（`connection.rpc.handle`）是**一次性返回值**：host 侧
响应在 `rpcFetchHandler` 里整体 buffer 成单个 JSON 再 `Response.json()` 返回，
没有插件可用的 server→client 推送面。框架自带的两条推送路都不通：

- **WebSocket mux**（`/api/remote.mux` 的 stream-protocol）挂在 Typert Gateway
  上，浏览器侧要 `remote.$mount` 手写 strict zod 描述符（仓库内 codegen 生成，
  插件手写成本高、无文档）；
- **转发事件** `remote.$on` 是**闭集白名单**（19 个固定事件），且注册位单座。

可行路线是 **`connection.fetch.register` 的 Exact Fetch 路由**（`/api` 下，
GET/HEAD/POST，响应体由 http-bridge **逐块带背压流出**，注释明说为流式
响应设计；webserver 的 gzip 中间件显式豁免 `text/event-stream`）：

- 自动继承 Connection 的 Host/Origin/cookie 鉴权栅栏，无需自接
  `requestRejection`；
- 官方在产先例：session-log-export（流式 ZIP 下载）、client-hmr
  （`/plugins/events` SSE 通道）、session-controller media-references；
- 浏览器插件 bundle 跑在页面主 realm（同源 classic script 装载），fetch +
  `response.body.getReader()` / EventSource 全可用，主文档无 CSP。

**真机发现的版本落差**：本机安装的 dsh 运行时是 0.1.1-rc.2，其 connection
服务（`@deepseek-ai/dsh-client-connection`）**只有 `rpc`，没有 `fetch.register`**
——该 API 在上游 main 分支才有（npm `next` 0.1.5-rc.2 起可用）。因此注册
做成**双路**：

1. **首选 `connection.fetch.register`**（新运行时）：自带鉴权栅栏；
2. **兜底 `webServer.register` exact 路由**（`@deepseek-ai/dsh-host-webserver`，
   rc.2 即有；`WebRoute` 注释明说可挂 SSE，client-hmr 的 `/plugins/events`
   同款）+ 自写 node:http ↔ fetch 适配器（Request 构造带 AbortController
   signal，`res.close` 未完成即 abort → request.signal；Response 体逐块
   背压写回）。webServer 路由表 **exact 先于 prefix 命中**，故
   `/api/input-assist/stream` 能压过 connection 占据的 `/api` 前缀路由。
   该路不在 connection 鉴权栅栏内，自接 **Host/Origin 栅栏**：放行同源
   浏览器请求与无 Origin 的本机客户端（curl），403 跨源请求——跨源也
   读不到响应（无 CORS 头），栅栏拦的是驱动式 POST 烧 token；
3. 两条都注册不上（极老运行时）则静默跳过——浏览器 404 自动降级 RPC。

## 3. 方案

```
浏览器半边                                             host 半边
防抖回调 → fetch POST /api/input-assist/stream ──▶ connection.fetch.register 流式路由
  （JSON body: prefix/suffix/requestId）             ├ 前置校验与 complete 端点对齐
  res.body.getReader() 解析 SSE 帧                    ├ streamFimCompletion()（NovAI 平移）：
  每 delta → rAF 合帧 setAssist({suggestion})   │    POST {base}/completions stream:true
  done 帧 → 终态归一化写回（host 单源）          │    SSE 解析 → onDelta 回调
  Tab/Esc/重调度 → AbortController + 既有           └ 上游文本以 SSE 帧回写 ReadableStream
  cancel RPC 双路断开
```

- **帧协议**（自定义、极简）：`data:{"delta":"片段"}\n\n` 增量；
  `data:{"done":"<host 侧归一化全文>"}\n\n` 终态（`normalizeSuggestion`
  留在 host——前缀语义、200 字截断等归一化逻辑单源）；`data:{"error":"…"}`
  流中失败；流关闭即结束。前置失败（no-api-key）发生在流开始前，回非 2xx
  JSON `{reason}`，浏览器按 RPC 错误形状复用处理。
- **上游客户端** `streamFimCompletion`（src/completion.ts，NovAI 平移）：
  `stream:true` 请求体；两级跨 chunk 缓冲（`TextDecoder({stream:true})` 防多
  字节截断 + `split('\n\n')` 后 `pop()` 留残段防 JSON 行被网络分片切开，
  CRLF 规整）；`choices[0].text` 主读、`delta.content` 兜底；`[DONE]`/坏行跳过。
- **空闲超时替代总超时**（src/abort.ts `resettableIdleSignal`）：每收到一个
  chunk 重开 10s 计时器——慢而稳的流不会被误杀，卡死的流最多 10s 断开；
  外部取消信号联动方式与 `linkedTimeoutSignal` 相同。
- **取消全链复用**（docs/12 的铺垫在这兑现）：流式路由把请求登记进与 RPC
  handler **共享的 `inflight` 表**（`createHandler` 加可选注入参数），既有
  `cancel` 端点零改动即可断流；浏览器侧 `abortCompletionRound()` 增加一行
  `completionStreamCtrl.abort()`，断 fetch → host `request.signal` → 上游
  abort，双路冗余。
- **Tab 流中采纳不断流**（NovAI 同款语义）：流内簿记 `streamAccumulated`/
  `streamAccepted`，Tab 后剩余建议 = `accumulated.slice(accepted)`，在途
  delta 继续追加到末尾；为此 `onDraftChanged` 的 `justAccepted` 分支改为
  **跳过 cancel 与序号递增**（原来无条件取消——非流式下响应已到无损，流式
  下会杀掉在途流）。done 帧仅在无采纳时直接采用（归一化全文与已采纳偏移
  无法跨映射），有采纳时本地切片收尾（trim 尾空白），且不回写 Tab 已更新
  的 `sugDraft/sugRev`。
- **rAF 合帧渲染**：自制 snapshot store 没有 Vue 式批处理（NovAI 每个 delta
  直写靠响应式合帧），flush 帧回调里一次性取「当下」的 accumulated/accepted
  切片——Tab 同步改 accepted，帧回调自然读到新值，不会闪回已采纳文本；
  最坏 60fps 一次镜像层重建。
- **降级矩阵**（冗余设计核心）：
  1. 上游返回非 SSE（content-type 为 JSON，网关忽略 stream 参数）→ host
     整读 JSON 按单 delta + done 发出，用户无感；
  2. host 是不带 fetch 路由的旧版本（client bundle 热更但 host 未重启）→
     fetch 回 404，置模块级 `streamRouteDown`，本次及后续自动走既有 RPC
     `complete` 非流式（每次页面加载重新探测）；
  3. 用户关 `completionStream` 开关 → 浏览器直接走 RPC 非流式（原路径不动）。
- **范围**：LLM 校对层维持非流式——结果是带 offset 的结构化 JSON，渐进
  渲染解析难、收益小。

## 4. 验证

`npm test` 115 例全过（新增 20 例）：

- `test/abort.test.js` +3：持续 reset 不到期 / 停 reset 后到期 / 外部联动 +
  已 abort 立即联动 / dispose 摘除；
- `test/completion.test.js` +8：SSE 主路径累积与 delta 序、`delta.content`
  兜底与 text 优先、请求体 `stream:true` 与 CRLF 行尾、**同一 JSON 行网络
  分片切断（含多字节字符字节级三段切）**（NovAI 一直缺的用例）、空闲超时
  AbortError、外部信号流中 abort（已收 delta 已回调）、非 SSE 整读降级、
  HTTP 错误同文案；
- `test/stream-route.test.js`（新）8 例：delta/done 帧序列与 host 归一化、
  no-api-key 前置失败 JSON reason、prompt 过短/开关关闭早退空 done、非 POST
  405、**共享 inflight 表 cancel 即断上游且无 error 帧**、客户端断开
  （request.signal）同路传导、无 requestId 兼容、**webServer 兜底桥集成**
  （真 node:http 服务器：无 Origin 放行流出 SSE 帧、跨源 403、同源放行、
  GET 405）；
- `test/settings-card.test.js` +2：`SETTINGS_FIELDS` 11→12 + completionStream
  toggle 暂存/默认值；bundle 出口 `parseStreamFrames` 帧切分（跨分片残余、
  CRLF、`data:` 前缀容忍）；
- `test/handler.test.js`：config.get/set 覆盖新键类型清洗。

真实运行时探针（dsh 0.1.1-rc.2，webServer 兜底路注册成功）：

- `POST /api/input-assist/stream`（空 body，curl 无 Origin）→ 200 +
  `data: {"done":""}` 早退帧（prompt 过短路径，符合设计）；
- 跨源 POST（`Origin: http://evil.example`）→ 403（Origin 栅栏生效）；
- `/plugins/dsh-input-assist/client.js` → 200（浏览器半边正常装载）。

## 6. 遗留

- LLM 校对层维持非流式（范围决策，见 §3）；
- `streamRouteDown` 是会话级标志，host 升级后需重载页面才会重新探测流式
  路由（与 client bundle 热更节奏一致，可接受）。
