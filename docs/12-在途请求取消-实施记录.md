# 开发记录 · 在途请求取消

日期：2026-09-13 · 对应 README 状态清单「流式中途取消」的取消半边（原最后一项待办）。

## 1. 背景与问题

补全（FIM）与 LLM 校对两路请求都是**非流式**、经 host 半边代理发出。当请求变得
过时（用户继续打字、按 Esc、关开关），浏览器侧只有**序号守卫**兜底——请求照跑
不误，响应回来对不上序号就丢弃。这带来三个实际问题：

1. **白花钱**：连续打字每次停笔都发新请求，旧请求在服务端跑完整个生成、照常
   计费，产出注定被扔掉（FIM 8s / LLM 12s 的硬超时是唯一上限）。
2. **Esc 后 ghost 复活**：请求在途时按 Esc 只清了 UI 状态（`sugRev: -1`），
   没有中断请求；响应落地时序号守卫仍然匹配，灰字会自己弹回来。
3. **关开关后迟到响应**：`completionEnabled` 关掉的瞬间不触发草稿变化，
   在途响应到达后照常写入状态。

cordis RPC 是一次性返回值，没有内置的中途取消通道，所以需要自己搭。

## 2. 方案

**requestId + host 注册表 + cancel 端点 + `cancelled` 错误码**，三段贯通：

### 信号层（src/abort.ts，新文件）

`linkedTimeoutSignal(timeoutMs, external?)` 把「外部取消信号 + 每调用超时」
联动成一个喂给 fetch 的 signal。手工联动（controller + setTimeout +
`addEventListener('abort')`）而非 `AbortSignal.any`，兼容更老的 Node 运行时；
调用 settle 后必须 `dispose()`（清计时器、摘监听）。

`requestFimCompletion` / `llmProofread` 新增可选 `signal` 参数，内部与原超时
联动（原 `AbortSignal.timeout` 语义不变），try/finally 保证 dispose。

### host 侧（src/index.ts）

- `createHandler` 闭包内建 `inflight: Map<requestId, AbortController>`；
  `complete` / `proofread` 带 `requestId` 时登记，settle 后 finally 摘除；
- 新端点 `cancel`：按 id 取 controller `abort()`，未知 id（已 settle / 从未
  注册 / 旧请求）幂等返回 `{ cancelled: false }`；
- 被 abort 的请求以 `code: 'cancelled'` 的 RpcError 收场——**必须用传输层
  错误码枚举内的值**（自定义 code 会让整个响应被传输层 schema 拒掉），
  区分方式是 catch 后检查外部 `controller.signal.aborted`（超时 abort 的
  是内部联动信号，外部信号保持干净）；
- 不带 `requestId` 的旧客户端不注册，行为与旧版完全一致。

### 浏览器侧（src/client.ts）

每次出站请求带 `nextRequestId()` 生成的 id（自增序号 + `crypto.randomUUID()`
随机段——**多标签页共用同一 host 实例**，必须跨标签页不撞号，故不做"取消
全部"）。四个触发点：

| 触发 | 动作 |
| --- | --- |
| 重新打字（`onDraftChanged` 重调度） | cancel 两路在途请求 + 递增序号 |
| Esc（建议可见） | cancel 补全在途 + 递增序号（迟到响应不再复活 ghost） |
| Esc（错别字忽略本次） | cancel LLM 校对在途（用户已表态不需要结果） |
| 关开关 | `configStore.subscribe` 监听——按钮 / 设置卡片 / settings.yaml
热同步任一路径都写进 store，一处覆盖；同时清残留建议状态 |

cancel 是尽力而为的 fire-and-forget：host 是不带 cancel 端点的旧版本、或网络
瞬断，都静默放过（序号守卫仍然保底不显示过期结果）。响应路径对
`code === 'cancelled'` 静默早退，绝不写 error 状态（否则 Esc 会弹"请求已取消"
错误条）。

## 3. 坑：Node 类型剥离下的 `.js` 指定符

`node --test` 直接按 .ts 加载 src 模块（类型剥离），**不会**把 `./abort.js`
重写到 `./abort.ts`——此前 src 内的跨模块值导入只存在于 client.ts（走构建
产物，rolldown 会做 .js→.ts 映射），所以一直没暴露。修法：src 内跨模块值
引用写 `.ts` 指定符（tsconfig 本就开了 `allowImportingTsExtensions`，测试
文件一直这么用）；纯类型导入不受影响。

## 4. 验证

`npm test` 91 例全过（新增 15 例）：

- `test/abort.test.js`（新）：外部 abort 联动 / 已 abort 立即联动 / 超时
  到期 / dispose 后不再触发无监听残留；
- `test/completion.test.js` +3：外部信号 abort 以 AbortError 拒绝 / 未取消
  的 signal 不影响正常返回 / 预先 abort 立即拒绝；
- `test/proofread-llm.test.js` +1：llmProofread 外部信号 abort；
- `test/handler.test.js` +4：complete 在途 cancel → `cancelled` 收场 +
  settle 后注册表摘除（再 cancel 幂等 false）/ proofread 同路 / 不带
  requestId 的旧客户端不受影响 / 缺 requestId 报 internal。

真实 Chrome 真机验收（2026-09-13，自动化浏览器 + 本地慢速 mock FIM 服务）：

- **方法**：临时把 `completionBaseUrl` 指向本地 mock（POST 挂 6s 才响应，
  记录每个连接是否被客户端提前断开），彻底消除「API 响应跑赢打断动作」的
  竞态，并从**服务端侧面**直接观测断开；settings.yaml 测后恢复原值；
- **基线**：请求完整走通 mock → ghost 显示 mock 文案（链路无回归）；
- **重调度断开**：在途时继续打字 → mock 记录旧请求 `aborted: true`、
  页面发出 1 个 cancel RPC、新请求正常排队、无过期 ghost；
- **Esc（在途）**：按 Esc 后 mock 4ms 内看到断开、cancel RPC 发出、
  ghost 不复活、无错误条；
- **Esc（防抖窗口内）**：请求根本不发出，无 ghost（本次验收抓到的缺口
  修复，见下「真机验收发现」）；
- **Esc（建议可见）**：立即关闭 ghost（与既有真机手测一致）；
- **关开关**：在途时点「补」关闭 → mock 记录断开、无迟到响应、无错误条，
  重开后不冒旧建议。

### 真机验收发现的缺口（已修）

初版 Esc 只取消「已发出」的在途请求（`completionReqId !== ''`），**漏了防抖
窗口内还没发出的排队轮**：Esc 落在停笔后 800ms 内时定时器照常触发、请求
照发、ghost 迟到上屏。修复为 `completionRoundActive()`（排队
`completionTimerPending` 或在途）+ `abortCompletionRound()` 统一作废
（清定时器 + 断在途 + 作废迟到响应），三处触发点（无建议 Esc / 建议可见
Esc / 关开关 watcher）全部走它；开关 watcher 顺带补了 `clearTimeout(llmTimer)`。
另在定时器回调加了一行 `debug({ completionReqId })` 写痕（请求在途窗口
可在控制台观测）。

### 自动化验收的方法论坑（记录备用）

- **隐藏镜像层的残留 span**：`syncMirror` 关闭 ghost 用 `display:none`、
  不清 innerHTML——`querySelector('.ia_ghost')` 查到的是不可见残留，
  断言必须看 mirror 的 computed display / getBoundingClientRect；
- **`__iaDebug` 是合并式覆写**：后续无关写痕会带着旧 key（completionRes
  等）再触发一次 setter，探针会看到「重复投递」假象；且 key 不随请求
  settle 清除，不能当在途信号轮询（重载页面可清）；
- **resource entry 在请求完成时才入表**：不能用于捕获「在途」瞬间；
- **合成键盘事件不可用**：Playwright `press()` 与 CUA keypress 都进不了
  插件的 document 级捕获监听器（真机物理键盘正常）；页面内派发标准
  `KeyboardEvent`（bubbles + cancelable）可完整走到处理器逻辑。
