# 19 · dsh 0.2.1-rc.2 适配

> 2026-10-23。dsh 0.2.x 重写了设置体系（plugin Config 持久化进 profile
> entry，旧 `SettingsProvider.register` 命名空间模型整体删除），并新增
> `engines.dsh` 版本门禁。本插件 0.8.0 同步适配，**不再支持 0.1.x 宿主**
> （engines 门禁在安装/启动时拦截；0.1.x 用户请留在 0.7.x）。同批带上
> 上一任务的句中补全渲染（ghost 按 sugCaret 定位，见下文顺带一节）。

## 背景

- dsh 0.1.7-alpha.1（commit `601d6761e4`）起设置体系重写：旧
  `SettingsProvider.register(ns, schema)` / `SettingsScope` /
  `settings.plugin.item` 客户端插槽 / `settingsScope` 服务全部删除；
  0.2.1-rc.2 是当前稳定线（npm `next` tag）。
- 新模型：插件 Config schema 字段标 `.volatile()`，Loader 校验后以
  **volatile 引用**注入 `apply(ctx, config)`，持久化位置 = profile 的
  插件 entry config（`profiles/<name>/cordis.patch.yml`）；写入走
  `SettingsForms` 服务（仍名 `'settings'`）的
  `settings.update(entryId, patch)`，ns = **profile entry id**。
- 新增 `engines.dsh` 兼容门禁（`evaluatePluginCompatibility`，包的
  `engines.dsh` range 单独裁决，否则查 `@deepseek-ai/dsh*` peerDeps）：
  不满足 → 拒装 / 启动禁用。

## 四处适配

### 1 · host 半边：volatile Config 重写（`src/index.ts`）

- `ConfigSchema` → 导出 `Config = z.object({ …每一项 `.default(默认值).volatile()` })`，
  `completionApiKey` 追加 `.role('secret')`（官方设置表单路径据此脱敏；
  本插件自有环回 config.get 不经该路径，行为不变）。
- 新增 `export interface Config`（12 个 `Volatile<T>` 字段）供 `apply` 签名。
- `apply(ctx: Context, config: Config)`：
  - `getConfig()` 逐字段 `config.x.get()` 实时取值（Loader 在
    `settings.update` 后更新引用，无需本地副本或监听）；
  - `updateConfig()` = `ctx.get('settings')`（未挂载抛可操作错误）+
    `settings.update(entryId, patch)`，`entryId = ctx.fiber.entry?.options.id`
    （无 Loader 挂载抛错；config.set 的 RPC 层把错误转成浏览器可见提示）；
  - `export default { Config, apply }`（Loader 读 `plugin.Config`）。
- 删除：`SettingsScope` 接口、`ctx.inject(['settings'])` + `register`
  调用、`import '@deepseek-ai/dsh-settings'` 副作用导入（改 type-only：
  `import type {} from '@deepseek-ai/dsh-settings'` +
  `'@deepseek-ai/cordis-plugin-loader'`，后者提供 `fiber.entry` 的类型合并）。
- 保留不动：环回 RPC / 流式路由 / 老运行时兜底（rpc.handle / webServer
  桥，engines 门禁外的手动安装场景仍可降级运行，settings 写入会得到
  明确报错）。

### 2 · client 半边：设置卡迁移 `plugins.bundle.config`（`src/client.ts`）

- 插座从 `settings.plugin.item`（keyed by 命名空间，已删除）换成
  **`plugins.bundle.config`**（keyed by **bundle 包名**，宿主在插件管理页
  侧栏 Plugins → bundle 详情页「配置」区以 `view: 'page'` 渲染）。
- 新增 `PluginConfigCard` 包装：`view: 'summary'` 渲染一句话描述，
  `'page'` / 缺省走原 `SettingsCard`（表单、暂存、词库区块、保存交互
  全部原样复用；宿主不传官方 form，数据通路仍是自有环回 RPC + 乐观更新）。
- `t` 仍由 locale 座位注入（注册声明 `locale: NS`），词典键零改动。
- `settings/document-updated` 监听保留：0.2.x 的 ns = entry id，本插件
  entry id 恰为 `input-assist`（cordis.patch.yml），与 `NS` 同值，
  过滤条件不用改。

### 3 · Tab 采纳改走 `insertText`（句中采纳光标不再跳末尾）

- 0.2.x 的 `InputActions` 新增
  `captureInsertion(): TokenSpan` + `insertText(text, span): boolean`
  （CAS 于 draftRev；官方契约注明 *the caret lands after the insertion*）。
  这解决了 0.1.x `setDraft` 固有的「替换整份草稿 + 光标落末尾」限制——
  句中逐词采纳后光标留在原地，ghost 继续跟随。
- Tab 处理器新分支：两者都在则
  `insertText(chunk, captureInsertion())`，返回 false（draftRev 已变 /
  编辑器锁定）回退原 setDraft / execCommand 路径；`sugCaret` 偏移语义
  不变（`caret + chunk.length` 与 insertText 的落点一致）。
- `TokenSpan` / 两个方法在 `InputActions` 接口上声明为可选（旧运行时
  特性检测回退）。

### 4 · 版本与依赖（`package.json`）

- `version` 0.7.1 → **0.8.0**；新增
  `engines: { dsh: ">=0.2.1-rc.2 <0.3.0" }`。
- dependencies：移除 `@deepseek-ai/dsh-settings`（不再有运行时导入），
  `@deepseek-ai/schemastery ^3.18.2 → ^3.18.5`（`.volatile()` 所需）。
- devDependencies：cordis `^4.0.2 → ^4.0.5`（`Volatile` 类型导出），
  新增 `@deepseek-ai/dsh-settings ^0.2.1-rc.2`（type-only，`settings`
  服务声明）、`@deepseek-ai/cordis-plugin-loader ~1.0.6`（type-only，
  `fiber.entry`）。
- peerDependencies：cordis `^4.0.1 → ^4.0.5`。pnpm 安装时的 peer 警告
  （cordis / react missing peer）是预期的：两者由宿主运行时提供。

## 顺带：句中补全渲染（同批 0.8.0）

上一任务的改动也在本版一起发布：`buildMirrorHtml(text, issues, curIdx,
ghost, ghostCaret)` 纯函数化——ghost 按 `sugCaret` 定位渲染（落在 typo
span 内部顺延到 span 后），`ghostVisible()` 增加 `composerCaret() ===
a.sugCaret` 光标匹配（不匹配即隐藏，含 IME 组合期），`selectionchange`
监听驱动重同步，逐词采纳后 `sugCaret` 随吞入长度右移。配 7 组单测
（句中 / 句末 clamp / 相邻重叠 / span 内顺延 / 多行 / 空 ghost / HTML 转义）。

`npm pack` 出的 0.8.0 tarball 经 `dsh plugin --profile web add` 安装
（engines 门禁放行），DEEPSEEK_API_KEY 从本机凭证复制。ZCode 内置浏览器

| 项 | 结果 |
| --- | --- |
