# 开发计划 · 词库数据外置 + 用户自定义词库

日期：2026-09-11 · 状态：已实施（2026-09-12，按推荐决策 D1–D5；实施记录见
[09-词库外置与自定义词库-实施记录.md](./09-词库外置与自定义词库-实施记录.md)）

## 1. 背景与目标

现状：错别字词典层的全部数据（约 230 条整词映射 `WRONG_PHRASES` + 8 条上下文规则
`CONTEXT_RULES`）硬编码在 `src/proofread-dict.ts` 的对象/数组字面量里。更新词库 =
改 TS 源码，条目多、逗号/引号易错，diff 噪音大；且最终用户无法补充自己领域的错词
（医学术语、团队黑话、输入法高频误打）。

目标：

1. **词库外置**：数据抽到独立数据文件（词库 + 规则），构建时读取并解析成现有数据
   结构，双侧产物（host ESM / client bundle）打包方式不变。后期更新词库只改数据文件。
2. **用户自定义词库**：允许用户在浏览器本地维护一份自己的词库（localStorage），
   与内置词库合并参与词典层扫描；不进 settings.yaml、不走 RPC，跨设备不同步。

非目标（本轮不做）：

- 不改 LLM 校对层（`proofread-llm.ts`）与补全链路。
- 不做词库的云端/配置文件同步（用户词库只在本浏览器）。
- 不向用户开放上下文规则（正则）编辑——安全与复杂度原因，见 §4 D3。

## 2. 现状梳理（改造涉及的接线点）

| 位置 | 现状 | 改造后 |
| --- | --- | --- |
| `src/proofread-dict.ts` | 类型 + 数据字面量 + `maskForScan` + `scanLocalTypos` | 类型 + **纯扫描/解析函数**；数据移出，由生成模块提供 |
| `src/index.ts:176` | RPC 兜底路径调 `scanLocalTypos(text)`（`llmOnly` 时为空） | 不变，继续用**内置**词库（用户词库只在浏览器侧） |
| `src/client.ts:628` | 词典层 200ms 防抖本地扫 `scanLocalTypos(draft)` | 改调合并词库的扫描入口（内置 + 用户词库） |
| `tsdown.config.ts` | 词典作为普通本地模块打进两入口 | 不变（生成模块仍是普通 TS 模块） |
| `test/proofread-dict.test.js` 等 | 直接测字面量与扫描 | 全量保留语义，补新用例 |

关键事实：client 调校对 RPC 时带 `llmOnly: true`（`src/client.ts:634`），所以 host
半边的 `scanLocalTypos` 只是兼容兜底，**用户词库不需要也不能同步到 host**——不会出现
两层结果不一致的问题。

## 3. 总体设计

### 3.1 数据文件（新增 `data/` 目录，仓库根）

**词库 `data/zh-wrong-phrases.txt`** — 行式纯文本，一行一条，手工编辑最友好：

```
# 错词 => 标准词；# 开头为注释行，空行忽略
迫不急待 => 迫不及待
一如继往 => 一如既往
白壁无瑕 => 白璧无瑕
白璧无暇 => 白璧无瑕
```

**规则 `data/zh-context-rules.json`** — 条目少、结构复杂（正则 + 替换模板 + 理由），
用 JSON 而非塞进 txt：

```json
[
  {
    "pattern": "登陆(系统|网站|网页|账号|账户|帐号|平台|页面|界面|邮箱|后台)",
    "flags": "g",
    "fix": "登录$1",
    "reason": "进入系统/账号用「登录」"
  },
  {
    "pattern": "必需(要)?(做|去|先|完成|配合|遵守|坚持|努力|学习|经过|通过)",
    "flags": "g",
    "fix": "必须$1$2",
    "reason": "后接动词用「必须」"
  }
]
```

现在的 `fix: (m) => ...` 函数改为**替换模板字符串**（`$1`/`$2` 引用捕获组，未参与
匹配的可选组替换为空串），加载时装配回函数——JSON 可序列化，语义与现有 8 条规则
一一对应（`$1 ?? ''` 的空组语义由装配函数统一处理）。

### 3.2 构建接线：生成器脚本 + 生成物入库（决策 D2，推荐项）

新增 `scripts/gen-dict.mjs`（零依赖 plain node 脚本）：

- 读 `data/zh-wrong-phrases.txt` + `data/zh-context-rules.json`；
- 校验：错词非空且不含空白、`=>` 两侧去空格、规则 pattern 可 `new RegExp`、模板
  引用的组号不越界；非法行/条目直接报错退出（构建期拦截，不静默丢弃）；
- 生成 `src/proofread-dict-data.generated.ts`：

```ts
// 由 scripts/gen-dict.mjs 从 data/  生成，勿手改；重新生成：npm run gendict
import type { ContextRule } from './proofread-dict.js'

export const WRONG_PHRASES: Record<string, string> = {
	'迫不急待': '迫不及待',
	// ...
}

export const CONTEXT_RULES: ContextRule[] = [
	{ regex: /登陆(系统|网站|…)/g, fix: (m) => applyTemplate('登录$1', m), reason: '进入系统/账号用「登录」' },
	// ...
]
```

  正则字面量用 `new RegExp(pattern, flags).toString()` 生成，天然转义无注入问题。

- **生成物提交进 git**：干净 clone 不跑生成器也能 `tsc --noEmit` 与构建；词库更新的
  PR 里 diff 直接可评审。CI 加一致性守卫：`npm run gendict && git diff --exit-code -- src/proofread-dict-data.generated.ts`，防手改生成物或忘同步。

npm scripts 调整：

```diff
- "build": "tsdown",
+ "gendict": "node scripts/gen-dict.mjs",
+ "build": "npm run gendict && tsdown",
```

`typecheck` / `test` / `prepack` 不动（生成物入库，tsc 直接可查）。生成器幂等
（同输入同输出，含稳定排序），这也是 CI 守卫的前提。

### 3.3 `src/proofread-dict.ts` 重构为纯逻辑模块

数据移出后保留：类型（`TypoIssue`/`ContextRule`）、`maskForScan`、扫描核心、
新增解析与装配函数。对外 API：

```ts
/** 行式词库文本 → 词表；返回 { phrases, errors: [{line, message}] }，非法行不进词表 */
export function parseDictText(text: string): { phrases: Record<string, string>; errors: ParseError[] }

/** 模板字符串 → fix 函数（$1/$2 替换，未匹配组 → 空串） */
export function applyTemplate(tpl: string, m: RegExpExecArray): string

/** 合并词典：用户词覆盖同错词内置项；orig === fix 的条目视为用户声明正确，扫描跳过 */
export interface DictBundle { phrases: Record<string, string>; rules: readonly ContextRule[] }
export function mergeDicts(builtin: DictBundle, user?: Record<string, string>): DictBundle

/** 核心扫描（纯函数，词典由调用方传入） */
export function scanWithDict(text: string, dict: DictBundle, limit?: number): TypoIssue[]

/** 向后兼容入口：内置词库直扫（host 兜底路径与既有测试继续可用） */
export function scanLocalTypos(text: string, limit?: number): TypoIssue[]
```

`scanLocalTypos` 内部改为 `scanWithDict(text, builtinBundle)`，`builtinBundle` 由
生成模块装配——`src/index.ts` 与既有测试零改动。

### 3.4 用户自定义词库（client 侧）

**存储**：localStorage，key `dsh-input-assist:user-dict:v1`，**值存原始行式文本**
（与 `zh-wrong-phrases.txt` 同语法：`错词 => 正词`、`#` 注释、空行忽略）。存原始
文本而非解析结果：与编辑框内容一一对应、天然就是导入/导出格式、解析逻辑单一。

**合并语义**：

- 用户词与内置词同错词 → 用户版覆盖（可修正内置词的"标准词"写法）；
- `错词 => 错词`（自映射）→ 该错词不再报错，即**禁用内置词**的唯一口子；
- 用户词库不参与上下文规则（本轮不开放，D3）。

**扫描接线**（`src/client.ts`）：200ms 词典层防抖回调里

```ts
const userText = localStorage.getItem(USER_DICT_KEY) ?? ''
const user = parseDictText(userText)          // 解析失败的行直接跳过（保存时已拦）
setAssist({ dictIssues: scanWithDict(draft, mergeDicts(builtinBundle, user.phrases)), ... })
```

每轮防抖重解析一次（千行文本解析 < 1ms，不值得做缓存；先简单，慢了再加 memo）。
保存词库后立即重扫当前 draft 一次（不等防抖），所见即所得。

**UI 入口**（决策 D4，推荐项）：v5.1 设置页卡片底部新增独立区块
「**自定义词库（仅本浏览器）**」，明确标注不随 settings.yaml 同步：

- 等宽 `textarea`（行式语法）+ 条数统计 + 非法行号提示；
- 自带「保存并生效 / 放弃」——**独立于卡片现有的暂存/保存状态机**（存储目标不同：
  localStorage vs settings.yaml，两个保存按钮语义不能混）；数字与必填本地校验风格
  沿用 v5.1 卡片交互（官方兄弟卡片同构）；
- 保存校验：单条错词 1..16 字且不含空白；总条数 ≤ 2000；有非法行则标行号、拒绝落盘。

**边界处理**：localStorage 写失败（隐私模式/配额满）→ 卡片内降级提示「无法写入本
浏览器存储」，不影响其余功能；读取 try/catch，坏数据当空词库。

## 4. 关键决策点（实现前请拍板）

| # | 问题 | 推荐 | 备选与代价 |
| --- | --- | --- | --- |
| D1 | 词库文件格式 | **txt 行式**（`错词 => 正词`）：增删词是主场景，一行一条最好编辑、diff 最干净 | 全 JSON：格式统一但 230 条引号逗号易错；全 txt：规则含正则+模板+理由，塞一行可读性差 |
| D2 | 构建接线 | **prebuild 生成 TS + 生成物入库**：类型链不变、干净 clone 可测、diff 可评审 | ① JSON 原生 import（rolldown 内联，零脚本）：需开 `resolveJsonModule`，txt 不可用且类型变宽；② rolldown 插件 load hook：tsc 需要 `.d.ts` 声明垫片，魔法多 |
| D3 | 用户词库范围 | **仅整词映射**：正则有 ReDoS/ catastrophic backtracking 与转义风险，不开放 | 开放受限规则（无嵌套量词白名单校验）：复杂度高，收益存疑，可等真实需求 |
| D4 | UI 入口 | **设置卡片内独立区块**：词库编辑属设置心智，复用卡片容器与样式 | dock 行弹窗：输入区离上下文近，但 dock 已承载错字导航+快捷键提示，再塞编辑器过载 |
| D5 | 禁用内置词语义 | **`错词 => 错词` 自映射跳过**：零新语法，语义自解释 | 专用前缀（如 `! 错词`）：更显式但多一套语法要文档化 |

## 7. 风险与边界

- **生成物漂移**：靠 CI 一致性守卫 + 文件头"勿手改"注释双保险。
- **localStorage 不可用**：所有读写 try/catch，词库功能整体降级为只读提示，不影响
  补全/LLM 校对。
- **词库质量**：用户词库是用户自己的责任域，插件只做格式校验不做内容过滤；内置
  词库继续维持"只收无歧义条目"的收录标准（README 承诺的零误报）。
- **性能**：合并后词典仍走 `indexOf` 逐词扫（现状即如此，词表量级 ~10³ 无压力）；
  用户词库 2000 条上限远低于可感知阈值。
- **迁移风险**：M1 要求"逐条一致 + 既有测试全绿"，行为回归在这一步拦截。

## 8. 验收标准

1. `npm test` 全绿（既有用例零修改通过，新增用例见 §6）。
2. 改 `data/` 下文件 → `npm run build` → 两侧产物词库随之变化，TS 源码零改动。
3. 设置卡片可编辑自定义词库，保存后当前输入草稿立即按新词库重新标红；换浏览器
   无该词库（本地性）。
4. `错词 => 错词` 能禁用内置词的报错。
5. CI 一致性守卫在手改生成物/漏跑生成器时能红。
