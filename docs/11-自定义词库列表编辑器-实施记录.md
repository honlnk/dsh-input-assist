# 开发记录 · 自定义词库列表编辑器

日期：2026-09-13 · 对应 README 状态清单「自定义词库」编辑体验改版（0.3 → 0.4）。

## 1. 背景与方案

0.3 的自定义词库是 textarea（一行一条 `错词 => 正词`），用户反馈「样式有些不雅」，
且行式语法对普通用户有门槛（要记 `=>`、看行号报错）。改为成对词条列表：

- 每行一对输入框：左错词、右正词；「＋ 添加词条」末尾追加、× 删除；
- 拖拽把手排序，键盘 ↑/↓ 等效（可访问性）；
- 增删与换位都有平滑动画（FLIP）；
- **存储格式不变**：仍是 localStorage 里 `错词 => 正词` 一行一条
  （key `dsh-input-assist:user-dict:v1`），pairs 只是编辑视图——旧数据无感升级。

同时清理了一个交互债：词库区块内原本有第二组「放弃/保存」按钮，与卡片页脚
那组重复。结论是区块内多余（页脚那组与官方兄弟插件卡片布局一致），词库草稿
并入卡片统一暂存流（dirty/blocked/保存/放弃同时覆盖配置与词库两路修改，失败
独立报告）。

## 2. 实现

### 纯逻辑层（src/settings-form.ts）

textarea 版的 `checkUserDictText`（行号报错）换成 pairs API：

- `parseUserDictPairs(text)`：文本 → pairs（跳过注释/空行/畸形行，兼容旧数据）；
- `serializeUserDictPairs(pairs)`：pairs → 文本（trim、跳过双侧皆空的行、保序）；
- `checkUserDictPairs(pairs)`：逐行首错 code（`blank`/`wrongSpace`/`rightSpace`/
  `tooLong`/`dup`，dup 标后出现的那行）+ 条数溢出（上限 2000、单词 ≤16 字不变）。
  溢出与行内错误正交：溢出只置 overflow + ok=false，不逐行报。

`parseDictText` 同步放宽：正词允许单个空格（`alot => a lot`），仅拒空值/连续
空白——与内置英文词库对齐，此前这类英文修正写进用户词库会被拒。

### 拖拽 + FLIP 基建（src/flip-list.ts，新文件）

纯 DOM 模块，不依赖 React：

- `moveItem(list, from, to)`：纯数组搬移；
- `snapshotRows(container)` / `applyFlip(container, before)`：FLIP 对。快照记
  `getBoundingClientRect().top`（含 transform），DOM 换位后清行内 transform、
  给位移差 >1px 的行加反向 `translateY`，强排（`offsetHeight`）后释放回 CSS
  过渡类（`.18s cubic-bezier(.2,.8,.2,1)`）；
- `startRowDrag(opts)`：pointer 事件拖拽。把手 `pointerdown` → `preventDefault`
  + `setPointerCapture`（try/catch）+ window 级 move/up/cancel。被拖行跟手 1:1
  （`.ia_udDrag` 置 `transition:none` + 阴影浮起），其余行按 ±(行高+gap) 让位；
  **目标位用 offsetTop/offsetHeight 中点计数**（transform 无关、行高可变安全）；
  松手 `onDrop(from, to)`。

### React 接线（src/client.ts SettingsCard）

- 行数据 `UserDictRow = UserDictPair & { id }`，id 来自模块级计数器（remount
  也不复用），id 作 React key 与 `data-flip-id`（FLIP 跨快照认行）；
- **无 flushSync 的 FLIP**：宿主不给插件注入 react-dom（无 `flushSync`，tsdown
  也不会引它），改为 useLayoutEffect 时机——`commitUserRows(next)` 先快照再
  setState，layout effect（DOM 已提交、未绘制）里 `applyFlip`。删除先加
  `.ia_udOut`（淡出+右移 130ms）再提交过滤后的数组，补位动画自然衔接；
- 添加行自动聚焦（`pendingFocus` ref + effect 聚焦新行错词框）；
- 脏检查：`userRows !== null && (有全空行 || serialize 与已存不一致)`——
  全空行也算脏，否则「只加一行没填」时放弃按钮不可用、空行清不掉（真机
  验证发现的坑）；保存时过滤全空行再落盘；
- 校验错误逐行内联（role=alert 红字在行下方），有问题时保存禁用；
- 删除按钮与输入框同款描边方框（32×32、同 border/radius/背景 token，hover
  边框与符号转红）。

## 3. 验证

- `npm test`：79/79（新增 4：parseUserDictPairs 兼容/丢弃与 alot=>a lot、
  serializeUserDictPairs trim/跳空/往返、checkUserDictPairs 全 code 精确数组、
  溢出正交；parseDictText 正词空格放宽 1 例）。测试桩 reactStub 相应补
  `useLayoutEffect`/`useRef`。
- 真机（dsh web + 本地 link 插件）：添加自动聚焦、真实输入、逐行报错、拖拽
  换位（合成事件与真实鼠标各一轮，flipId/值跟随、transform/类清理干净）、
  保存落 localStorage、自映射禁用内置词（rescanDict 生效）、删除淡出+补位、
  放弃、折叠/展开持久、空行脏检查修复回归、计算样式（输入框等宽 218px、
  删除按钮 32×32 与输入框同 border/radius/背景、恰好 1 组页脚按钮）。

## 4. 遗留

- 换浏览器迁移只剩手动改 localStorage（列表 UI 没有批量粘贴入口）；如需要
  可后续加「导入/导出文本」入口，格式就是现有的一行一条。
- LLM 层不读用户词库（自映射只禁用词典层检出），仍是文档化的设计边界。
