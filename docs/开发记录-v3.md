# 开发记录 v3 — NovAI 化改版（ghost text + 词典层下沉）

日期：2026-08-23

## 动机

v2 的补全建议条（悬浮横条）有两个问题：

1. **视觉差**：建议条盖在输入文字上，建议内容与快捷键提示混在一条里，看不出哪个是要补的字（对照 NovAI 项目的内联 ghost text 差距明显）
2. **延迟不合理**：词典层（本地扫描，微秒级）被绑在 LLM 请求链路上——等 1000ms 防抖 + 等整个 LLM 网络往返，红字才出现

## 改动清单

### ghost text（对齐 NovAI 的 GhostTextOverlay 方案）

- 建议本体从悬浮条挪进**镜像层**：已输入文字渲染为透明 span 撑布局，末尾追加 `.ia_ghost` 灰色 span（`--dsw-alias-label-tertiary`），建议自然落在光标后
- 镜像层因此双用：错别字红字 + ghost 建议，`syncMirror()` 按「有错字 OR 有建议」任一条件显示
- `input.overlay` 插槽的建议条瘦身成 11px 超薄提示（`Tab 采纳一词 · Esc 关闭`），不含建议内容；loading 转圈条直接删除
- **Tab 逐词采纳**：`Intl.Segmenter('zh', { granularity: 'word' })` 每次吞一个词（空白随下一段、标点并入下一词），`Shift+Tab` 全量；吃光后自动再调度一轮
- **justAccepted 守卫**：部分采纳后 `setDraft` 会触发 `onDraftChanged`，若 draft === sugDraft 且仍有剩余建议，跳过这次重调度（避免 ghost 闪烁，对齐 NovAI「吃光才重新请求」）

### 校对两层拆分（各自防抖）

| 层 | 位置 | 防抖 | 说明 |
| --- | --- | --- | --- |
| 词典层 | **浏览器本地** | `proofreadDictDebounceMs` 200ms | 零成本即时标红，不走 RPC |
| LLM 层 | host | `proofreadDebounceMs` 800ms | 与补全（800ms）几乎同时发出、同时返回 |
| 补全 | host | `completionDebounceMs` 800ms | 原 600ms |

- 词典代码以 `DICT-SHARED-BEGIN/END` 标记块在 `proofread-dict.js` 与 `client.js` 间逐字共享；`test/dict-sync.test.js` 用 eval + 行为对比（词典表深等、规则正则/文案一致、词典命中/上下文规则/掩码样本输出一致）防漂移
- host `proofread` 端点新增 `llmOnly: true` 入参，跳过 host 侧词典扫描（保留仅为兼容旧调用方）
- 两层结果在浏览器侧合并（`mergeIssues` 逻辑内联进 client.js，词典优先、重叠剔除）
- `proofreadUseLlm: false` 时**完全不发校对 RPC**，零开销

## 踩坑

- **字面 NUL 字节**：`maskForScan` 里 `'\u0000'` 占位符经编辑工具写入时变成了真实的 NUL 字符，导致文件被识别为二进制、Edit 工具拒绝写入。修复为源码级转义序列 `'\u0000'`（6 字符），运行时等价
- **Node v24 `node --test test/` 目录参数被当模块解析**：报 `Cannot find module .../test`，测试脚本改为 `node --test test/*.test.js`

## 验证

- `npm test`：35 用例全过（28 原有 + 5 词典同步 + 2 handler 新增）
- 浏览器实测：词典红字 200ms 出现；无 API key 时补全静默、不报错条（no-api-key 提示保留在 overlay）
