# 开发记录 · 模型目录拉取 + 默认模型迁移

日期：2026-09-11 · 对应 README 状态「v5.2 模型目录拉取」。

## 1. 背景

DeepSeek 官方已于 **2026-07-24** 停用旧模型名 `deepseek-chat` / `deepseek-reasoner`（旧 chat 名映射至
V4 系后彻底下线），当前推荐名为 **`deepseek-flash`**（V4.1 Flash）。本插件默认值仍写死 `deepseek-chat`，
新装用户补全/校对实际已失效；且模型名无图形化选择，用户手填无从得知可用列表。

## 2. 实现

- **host 半边**：
  - `src/completion.ts` 新增 `platformBaseUrl()`（从 FIM 基址剥 `/beta`、`/v1` 尾段——DeepSeek 的
    模型目录在平台根 `GET /models`，与 FIM 的 `/beta/completions` 不同基）与 `listModels()`
    （OpenAI 兼容目录解析，去重排序，8s 超时）。
  - `src/index.ts` 新增 RPC `models.list`：复用 `resolveApiKey` 凭证链；无 key 返回
    `reason: 'no-api-key'`，拉取异常返回 `reason: 'fetch-failed'` + 短 message——一律 ok 载荷，
    不走传输层错误码（与 complete 的 no-api-key 模式一致）。
- **client 半边**（设置卡片）：
  - 两个模型字段（completionModel / proofreadModel，`settings-form.ts` 加 `model: true` 标记）为
    自定义组合框：输入框（自由文本）+ 与输入框同款样式的 34px 方块按钮（官方 chevron SVG，展开
    翻转 180°）+ absolute 自定义下拉面板（卡片 z 层之上；面板头 = 模型计数 + ⟳ 刷新，选项 hover
    高亮、当前值蓝色 + ✓）。
  - 交互：点 ▾ 打开面板即拉最新目录（旧列表先展示、回来原地替换；不再有面板内刷新按钮，也
    不再在展开卡片时预拉）；外点（mousedown capture）与 Esc 关闭面板；两个模型字段共享目录；
    拉取失败面板内给失败文案，输入框始终可手填（自定义端点模型名）。
  - 选回原值后仍计为暂存（Save 亮）：与上游设置语义一致——显式写入即"钉住覆盖项"，值等于默认也是覆盖。
- **默认值**：`DEFAULT_CONFIG` 两个模型字段 `deepseek-chat` → `deepseek-flash`（host schema 默认
  同源引用，一处改动双侧生效）。已显式存过旧名的 settings.yaml 不做静默改写——用户可在卡片里
  下拉一键修正。

## 3. 验证

- `npm test`：49/49（新增 completion 3：platformBaseUrl 剥段/listModels 解析/异常形态；handler 3：
  models.list 成功·no-api-key·fetch-failed；settings-card 补 model 标记与 fetchModels 注入断言，
  react 桩补 useId）。
- 真机（重启 dsh 后）：展开卡片自动拉取，官方目录返回 `deepseek-flash` / `deepseek-v4-pro` 两项
  进下拉；两字段默认值已是 `deepseek-flash`（settings.yaml 无模型覆盖，schema 新默认直接生效）。

## 4. 遗留

- FIM `/beta/completions` 对 `deepseek-flash` 的建议质量/延迟仍归 M2.5 真机手感验收。
- dsh 自带的模型选择器（dsh-llm-deepseek 0.1.1-rc.2）尚不认识 `deepseek-flash`（只有 v4 系旧名），
  上游包更新后无影响——本插件模型名独立配置。
