## 踩坑记录（重要）

1. **RPC 响应有 schema 校验**：`error.code` 必须取自传输层枚举（`bad-request`/`internal`…），自定义 code（如 `no-api-key`）会让整个响应被拒、浏览器侧 promise reject。预期内的"失败"改用 `{ok:true, value:{reason}}` 表达。
2. **插槽组件的 `inject()` 选项必须提供组件用到的每个注入**：IssuesPanel 用了 `api.dismissIssues` 但 dock 注册没注入 `api` → 渲染期读 undefined 属性抛异常 → 面板静默消失。已改为 `api?.dismissIssues?.()` 双保险。
3. **启动器旗标顺序**：`dsh --patch x.yml web` ✗（web 子命令拒绝父级旗标）；正确：`dsh --profile web --patch x.yml -- <web-app 参数>`。
4. **`.credentials.yaml` 必须 `chmod 600`**，否则 dsh 启动直接报错。
5. **测试浏览器（ZCode IAB）的点击派发对本页主区域组件无效**（dsh 自家弹窗可以、主界面和我们插件的所有按钮都不响应 React onClick；键盘输入、fill、evaluate 正常）。几何/层级/pointer-events 均排查无异常，判定为 IAB guest 的 CDP 输入派发问题，**非插件 bug**。点击修复/开关的实际效果需在真实 Chrome 里验证（`inputActions.setDraft` 写草稿的机制已被官方 dsh-voice-input 插件在生产使用）。
6. 原生目录选择器在 IAB 中不可用 → 测试时直接往 `~/.dsh/storages/workspace.json` 注入 workspace 记录（uuid + realpath + title + 时间戳 + sessionIds: []）绕过。

## 与方案的偏差

- v1 补全为**非流式**（方案里是流式）：RPC 通道为请求/响应式，流式需事件推送，留到 M3；max_tokens 64 + 8s 超时下延迟可接受。
- 建议条形态（overlay 插槽）而非 ghost text：按方案分阶段执行，ghost text 属 M3。
- 错别字 LLM 层复用 `completionApiKey`/`completionBaseUrl`（方案里独立的 proofread 配置未做，模型名可单独配）。
