# dsh-input-assist · 调研与技术方案

> DeepSeek Harness（dsh）输入助手插件：为 Web UI 的聊天输入框提供 **AI 输入补全**（ghost 建议条，Tab 接受）与 **错别字检查**（实时检测，点击修复）。
>
> 本文档是项目立项文档，2026-08-23 完成调研，后续开发以本文档为基准。

---

## 1. 项目概述

### 1.1 要做什么

一个 dsh 双侧插件（host Node 半边 + browser 半边），在 dsh Web UI 的对话输入框（composer）上叠加两个能力：

1. **输入补全**：用户在输入框打字时，防抖调用补全接口（DeepSeek FIM），在输入框附近展示"接下来可能想输入的内容"，Tab 接受写回草稿。
2. **错别字检查**：实时（防抖）检查草稿文本中的疑似错别字，在输入框上方面板列出，点击即可替换修复。

### 1.2 为什么做

- dsh 插件生态（目录站收录 3588 个插件）中，**输入框补全类插件为零**，错别字方向只有文档级校对工具，没有输入框实时检查——两个功能都有空白。
- 补全的完整实现已在 NovAI 项目（`~/project/NovAI`）中验证过（FIM 接口、防抖、中文逐段接受、ghost text 展示），核心逻辑可直接平移。
- dsh 的输入框读写与 UI 插槽均为公开契约，技术路线已通过源码级调研确认。

### 2.3 dsh 输入框扩展能力（源码级确认）

> 源码 shallow clone 于 `/tmp/dsh-src`（如被清理可重新 `git clone --depth 1 https://github.com/deepseek-ai/deepseek-harness.git`）。关键文件：`packages/extensions/cordis-client-runner/src/client/slot-catalog.ts`（生成版插槽目录）、`packages/client/ui-conversation/src/client/input/contract.ts`（输入契约）。

**草稿读写（公开契约，无需 hack）：**

- 每个 session 作用域的插槽组件自带框架 props：`useInput`（selector 钩子）与 `inputActions`。
- `InputState`：含 `draft: string`（草稿全文）、`draftRev`（单调修订号，做变更检测）、`phase`、`queue` 等。
- `InputActions.setDraft(text)`：官方文档明言 "Single public draft write path (full next draft)"——补全写回、错别字替换都走这里。
- 输入框是**原生 textarea**，DOM 跨会话切换存活（`conversation.composer.bar` 契约原文）。

**可用 UI 插槽（均为 additive，不替换官方 UI）：**

| 插槽 | kind / scope | 用途 | 本项目用途 |
| --- | --- | --- | --- |
| `conversation.input.overlay` | list / session | 输入框浮层锚点（斜杠菜单 `MenuView`、命令弹窗在此） | **补全建议条** |
| `conversation.input.dock` | list / session | 输入框上方独占一行（官方 queue/todo/goal dock 在此） | **错别字检查面板** |
| `conversation.composer.dock` | list / session | 输入框下方状态行（官方 stats line 占用，可并存） | 状态提示（如"发现 2 处疑似错别字"） |
| `conversation.input.right` | list / session | 工具行右侧、发送键左侧的小控件（语音插件在此加麦克风） | 功能开关按钮 |
| `conversation.input.left` | list / session | 工具行左侧小控件 | 备用 |

**注册模式（浏览器半边）：**

```ts
return {
  inject: ['slots'],
  apply(ctx) {
    ctx.slots.inject('conversation.input.overlay', () => ctx.slots.register(
      { name: 'conversation.input.overlay', id: 'input-assist-suggest', order: 100 },
      SuggestBar,  // 组件用 React.createElement 构建
    ))
  },
}
```

浏览器半边约束（slot-catalog `CLIENT_NOTES`）：不能 `import` 任何东西；用 `React.createElement` 构建标记；CSS 通过 `styles.insert(css)` 注入；使用主题 CSS 变量（`var(--dsw-alias-label-primary)` 等）而非字面量颜色；不传 `priority`。

**参考插件（实现范本）：**

- `0nt-one/dsh-voice-input`（dsh-voice-input-web）：纯浏览器端，`conversation.input.right` 加麦克风按钮、识别文字填入输入框。零依赖范式。
- `FrankZhangIronly/dsh-composer-enter`：**双侧插件范本**。host 半边（Node）持有 settings 命名空间（`ui-composer-enter`，持久化到 `<dsh home>/settings.yaml`）+ loopback RPC 通道（`/composer-enter`，authority `loopback`）；浏览器半边渲染设置行 + document capture 阶段键盘拦截（IME 安全）。本项目直接采用此架构。

## 3. 技术方案

### 3.1 总体架构：双侧插件

```
┌─ dsh Web UI（浏览器）──────────────────────────┐
│ browser 半边（client 入口）                      │
│  · input.overlay  → 补全建议条（⇥ 接受：…）      │
│  · input.dock     → 错别字面板（点击修复）        │
│  · input.right    → 开关按钮                     │
│  · useInput(s=>s.draft) 响应式读草稿             │
│  · inputActions.setDraft(next) 写回              │
│  · Tab 接受：capture 阶段监听（IME 安全）         │
└──────────────┬ loopback RPC（仿 composer-enter）─┘
               │  /input-assist 通道
┌──────────────┴ host 半边（Node）────────────────┐
│  · FIM 补全代理：POST {baseUrl}/completions      │
│    （NovAI completion-client.ts 平移）           │
│  · 错别字检查代理：POST /chat/completions        │
│    小模型 + 低温 + JSON 输出                     │
│  · settings 命名空间 `input-assist`（settings.yaml）│
│  · API key 管理（优先复用 dsh 已配置凭证）        │
└────────────────────────────────────────────────┘
```

设计要点：

- **API 调用一律走 host 半边**：规避浏览器 CORS 不确定性；且 host 可读取 dsh 凭证服务（`packages/credentials`），若用户已在 dsh 配好 DeepSeek key 则免重复配置。
- **UI 一律 additive 插槽**：不占用任何 `shadows-shipped-ui`（替换式）座位，把 developer preview 破坏性变更的风险降到最低。
- **两功能共用**：同一 RPC 通道、同一防抖调度器（两个不同防抖参数）、同一配置命名空间与开关按钮。

### 3.2 功能一：输入补全

**触发**：浏览器半边用 `useInput` 监听 `draft` + `draftRev` 变化 → 防抖（默认 600ms，可配）→ 经 RPC 调 host 的 FIM 流式补全 → 流式返回文本。

**请求**（与 NovAI / deepseek-autocomplete 一致）：

```jsonc
POST {baseUrl}/completions        // 默认 https://api.deepseek.com/beta
{
  "model": "deepseek-chat",
  "prompt": "<光标前文本>",
  "suffix": "<光标后文本，可为空>",
  "stream": true,
  "max_tokens": 64,
  "stop": ["\n"]
}
```

**展示与接受（分两阶段）**：

- **M1 建议条**：在 `conversation.input.overlay` 渲染一条 `⇥ 接受：xxx…`，有建议且输入框聚焦时显示。Tab 接受：capture 阶段键盘监听（仅建议可见时拦截；`isComposing`/keyCode 229 放行——composer-enter 已验证此法），`setDraft(draft + suggestion)`。Esc 丢弃。斜杠菜单/命令弹窗打开时让位（读各自 store 判断，或建议条自身 order 靠后 + 检测 overlay 已有活动菜单则不显示）。
- **M3 ghost text（增强，可选）**：复刻 NovAI `GhostTextOverlay.vue` 思路——定位 textarea DOM，同位叠加透明层（已输入 `invisible` 撑布局 + 建议灰色），字体/行高取 textarea 的 computed style。属 DOM hack，官方 UI 改版需跟进，故放最后。

**逐段接受**（M3，从 NovAI 平移 `Intl.Segmenter` 逻辑）：Tab 一次接受一个中文"词"级片段，吃完自动续补下一段。

**中止与竞态**：NovAI 的三路竞速（read / 15s 空闲 / 用户 abort）+ 配置快照防竞态整体平移；draft 变更即 abort 上一轮。

### 3.3 功能二：错别字检查

**触发**：同一调度器，独立防抖（默认 1000ms，草稿 ≥ 4 字才检查），仅在文本"稳定"（无进行中补全请求）时发起。

**请求**（host 半边 → chat 接口，小模型如 `deepseek-chat`，`temperature: 0`）：

```jsonc
POST {baseUrl}/chat/completions
{
  "model": "deepseek-chat",
  "messages": [
    {"role":"system","content":"你是中文错别字检查器。检查用户文本中的错别字（含同音字误用、形近字误用）。只输出 JSON 数组，每项 {\"orig\":string,\"fix\":string,\"offset\":number,\"reason\":string}；无错别字输出 []。不要输出任何其他内容。"},
    {"role":"user","content":"<草稿全文>"}
  ],
  "temperature": 0,
  "max_tokens": 512,
  "response_format": {"type":"json_object"}
}
```

**展示**：`conversation.input.dock` 面板，仅在有问题时渲染（空数组渲染 null，与 overlay 契约一致）：每行 `orig → fix（reason）`，点击"修复"按钮 → 校验 `draft.slice(offset).startsWith(orig)`（防陈旧结果错位）→ `setDraft` 替换。`composer.dock` 可选显示一行摘要。

**边界**：检查结果带 `draftRev` 戳，草稿已变则丢弃；发送后草稿清空自动隐藏面板。

### 3.4 配置设计

settings 命名空间 `input-assist`（仿 composer-enter 的 `ui-composer-enter`，host 半边持有，持久化 `settings.yaml`）：

```yaml
input-assist:
  completion:
    enabled: true          # 总开关（右侧按钮也可切）
    baseUrl: https://api.deepseek.com/beta
    apiKey: ''             # 留空则尝试复用 dsh 凭证
    model: deepseek-chat
    debounceMs: 600
    maxTokens: 64
  proofread:
    enabled: true
    model: deepseek-chat
    debounceMs: 1000
```

## 5. 风险与对策

| 风险 | 对策 |
| --- | --- |
| dsh 处于 developer preview，契约可能破坏性变更 | 只用 additive 插槽与公开 `setDraft`/`useInput`；不用任何替换式座位；升级前跑 M0 验收 |
| ghost text 无公开 API，DOM hack 脆弱 | 放 M3 且做成可关闭的增强；M1 建议条方案完全契约内，随时可退 |
| FIM 流式 delta 在代理网关下字段不一致 | NovAI 已有 `text`/`delta.content` 双读兜底，平移 |
| 键盘拦截与斜杠菜单/命令弹窗冲突 | 仅建议可见时拦截 Tab；overlay 内检测其他菜单打开则让位；IME 安全照搬 composer-enter |
| 错别字结果陈旧错位 | 结果带 draftRev 戳；替换前 `startsWith` 校验；失败静默重查 |
| 延迟体验（FIM 首字延迟） | 流式 + 600ms 防抖 + maxTokens 64 + 15s 空闲超时；NovAI 遗留的"延迟验证"项在 M1 真机验证 |
