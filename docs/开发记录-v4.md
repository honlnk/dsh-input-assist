# 开发记录 v4 — TypeScript 重构

> 2026-08-23 · 目标：全量迁移到 TypeScript（strict），构建改用官方插件惯例的 tsdown，
> 词典从「双份拷贝逐字同步」升级为「单一源 + 构建器分发」。

## 动机

- 项目从 v1 走到 v3.2，`lib/client.js` 已经 1090 行，纯 JS 维护成本随体量上升（用户原话："我怕以后项目做大了 js 会扛不住"）。
- dsh 官方插件生态的惯例就是 TS 源码 + tsdown 构建，发布 `lib/index.js`（ESM + d.ts）与 `lib/client.js`（ModuleLoader 壳的 lazy-CJS bundle）。
- 调研确认：`dsh-typert-*` 三件套是 RPC/反射协议而非 TS 加载器；宿主 cordis loader 会把 `.ts` specifier 重写为 `.js` 再 import，所以**必须发布构建产物**，不能直接跑源码。

## 方案

### 目录结构

```
src/
  config.ts          NS/CHANNEL/默认配置/配置接口（两侧共享）
  proofread-dict.ts  词典层（原 DICT-SHARED 块的唯一源）
  proofread-llm.ts   LLM 校对层（prompt/解析/定位/合并）
  completion.ts      FIM 补全请求与建议规整
  index.ts           host 半边（settings schema、RPC 四端点、API key 回退）
  client.ts          浏览器半边（组件/镜像层/调度/快捷键）
tsdown.config.ts     双入口构建配置
lib/                 构建产物（gitignore，prepack 时构建）
```

### tsdown 双入口

```ts
// host：ESM + d.ts，node20；@deepseek-ai/* 与 react 保持外部依赖
{ entry: { index: 'src/index.ts' }, format: 'esm', dts: true, target: 'node20' }
// client：CJS + ModuleLoader 壳；react / dsh-client-runtime/client 外置（宿主种子模块提供）
{ entry: { client: 'src/client.ts' }, format: 'cjs', target: 'chrome110',
  outputOptions: { banner: 'window.__ModuleLoader__.load({id:...,factory:(require)=>{var module={exports:{}};...',
                   footer: 'return module.exports;}});' } }
```

要点：
- ESM 入口默认产物名是 `.mjs`，必须显式 `entryFileNames: '[name].js'`（package.json `main` 与 cordis 约定都是 `lib/index.js`）。
- 词典由 client.ts 直接 `import { scanLocalTypos } from './proofread-dict.js'`，构建时内联进 bundle——**DICT-SHARED 标记块与 dict-sync 防漂移测试从此消失**，单一源天然同步。
- client bundle 41KB（gzip 14KB），包含全部词典数据与 CONTEXT_RULES。

### 类型窄化（不引宿主内部类型）

`@deepseek-ai/dsh-client-runtime` 从 0.1.1-rc.2 起自带类型，`createSnapshotStore` 直接可用真类型；
其余宿主服务（slots/locale/connection/remote、组件 props）在 client.ts 顶部用结构化接口窄化
（`SlotsService`/`SlotProps`/`UseStore<T>`/`InputActions`…），只声明本插件实际消费的面，避免耦合宿主内部类型。

## 依赖调整

- `@deepseek-ai/dsh-settings` 从 `0.1.0-rc.6` 对齐到 `0.1.1-rc.2`（与运行时 0.1.1-rc.2 的 peer 图兼容，否则 ERESOLVE）。
- devDependencies 新增 `typescript@7`、`tsdown`、`@types/react@^18`（与 peer react 18 对齐，v19 类型对 createElement 重载不兼容）、`@deepseek-ai/dsh-client-runtime`（仅取类型 + 构建外置声明）。

## 迁移中的坑

1. **字面 NUL**：`'\u0000'` 一旦被编辑器写成真实 NUL 字节，文件被当二进制。统一用 6 字符转义序列。
2. **tsdown ESM 产物名**：见上，`.mjs` → 显式 `[name].js`。
3. **CJS 命名空间导出**：`export * as react from 'react'` 会生成 `__reExport` 包装，改用 `import * as react from 'react'` 保持旧 bundle 的 require 形状。
4. **Node 24 直接跑 TS**：单测 import `../src/proofread-dict.ts` 即可（type stripping），不需要额外编译步骤；但要注意源码必须是「可擦除」语法（无 enum / 参数属性）。
5. **React 18 类型对 `Record<string, unknown>` 的 api prop**：结构化接口用 `api?: object` 而非索引签名，否则具名接口赋值报 TS2322。

## 遗留

- tsdown `external` 选项有弃用警告（新 API `deps.neverBundle`），行为不受影响，升级 tsdown 时再迁移。
- dsh 进程未重启时 host 半边仍跑旧内存代码；RPC 契约未变所以无感，下次重启自然切换到新产物。
